<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter app -> Cloudflare Worker | Client-to-server HTTPS POST. Payload contains message metadata only (no recipient tokens — Worker resolves them server-side) |
| Worker -> Firestore REST API | Server-to-server HTTPS. Worker queries notification strategies and FCM tokens directly |
| Worker -> FCM API | Server-to-server HTTPS. Uses Service Account JWT for auth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-07-10 | Information Disclosure | Worker URL exposed in Flutter code | accept | Worker validates internally; no auth on endpoint (rate limiting could be added later) |
| T-07-11 | Spoofing | Client could send fake notifications | accept | Notification content limited to actual message data; no way to impersonate without Firestore write access |
| T-07-12 | DoS | Spam Worker endpoint | accept | Cloudflare free tier handles 100K req/day; campus app volume is far below this |
